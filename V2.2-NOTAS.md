# ENIGMA OS V2.2

## O que mudou
- Fluxo guiado da OS: Recebido → Em diagnóstico → Aguardando aprovação → Em reparo → Pronto → Entregue.
- Status não é mais alterado por uma barra manual; cada etapa avança por uma ação específica.
- Diagnóstico fica bloqueado até concluir a entrada.
- Orçamento passa a ter ação explícita de envio antes da aprovação.
- Peças podem vir do estoque ou ser lançadas como peça avulsa/sob encomenda.
- Peças avulsas entram no orçamento sem movimentar estoque.
- Vistoria fotográfica organizada por Entrada, Durante o reparo e Saída, com ângulo/tipo, observação e horário.
- Fotos novas usam o Supabase Storage quando o bucket `os-fotos` está disponível.
- Finalização do reparo exige checklist de testes finais antes de liberar para retirada.
- Entrega registra pagamento, forma de pagamento, garantia, observações e assinatura de retirada.
- Termos/assinaturas foram separados conceitualmente entre entrada, autorização e entrega.
- Histórico recebe eventos automáticos gerados pelo fluxo.

## Antes de publicar
1. Execute `SUPABASE-V2.2.sql` no SQL Editor do Supabase.
2. Depois envie os arquivos desta pasta para o GitHub, substituindo os da V2.1.
3. Aguarde o deployment automático da Vercel.

## Observação de segurança
O projeto atual ainda usa a chave pública do Supabase diretamente no front-end e não possui autenticação. As políticas do Storage desta versão são temporárias para manter o sistema funcionando. A próxima etapa estrutural deve ser autenticação + RLS por usuário/empresa.
